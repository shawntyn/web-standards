# JSON 声明什么，就渲染什么

统一的是协议转换与组件注册，不是固定页面模板，也不是 Markdown 排版。源 JSON 明确写出标题、正文、布局、组件参数及命名插槽；转换器不根据项目名称补标题，不根据描述补段落，不自动添加卡片、导航或交互工具。

## 两种结构，一一对应

业务记录中的 content 是一个显式根节点树。每个节点有 id、type、props，可按组件能力声明 children 和 slots。json-render 的 Spec 则使用 root 与 elements 节点字典，children 和 slots 引用节点 ID。

转换器只完成树到字典的转换：每个源节点产生一个目标节点，保持 ID、顺序、props 与插槽关系。h1 到 h6 是 Heading 的语义别名，分别对应 level 1 到 6；p 对应 Text。这是协议名称映射，不是额外创造内容。

```json
{
  "id": "overview",
  "type": "Stack",
  "props": { "gap": "lg" },
  "children": [
    { "id": "title", "type": "h1", "props": { "text": "产品概览" } },
    {
      "id": "intro",
      "type": "p",
      "props": { "text": "这里是数据明确提供的介绍。" }
    },
    {
      "id": "metrics",
      "type": "Grid",
      "props": { "columns": 2 },
      "children": [
        {
          "id": "members",
          "type": "Metric",
          "props": { "label": "成员", "value": "24" }
        },
        {
          "id": "tasks",
          "type": "Metric",
          "props": { "label": "任务", "value": "1280" }
        }
      ]
    }
  ]
}
```

上面的五个子节点与根布局共六个源节点，转换后仍只有六个节点。删掉 title，就不出现 h1；只提供一个 p 根节点，就只渲染这个段落，不会被强制包进文章、卡片或标题模板。

## 独立文件与不同布局

packages/data/src/projects/ 下的 atlas.json、orbit.json、field.json 分别独立维护。它们共享受限节点协议，但在数据中声明各自不同的组件树。Grid、Stack、Card 等布局不是 mapper 的默认选择。

packages/domain/src/content.ts 校验树；packages/render/src/projects/project-content-spec.ts 展平树；ProjectSpecViewRender 仅连接转换器与受信任 registry。项目 name、description 等元数据仍用于列表和 SEO，不隐式加入详情正文。Next.js 的路由布局只负责应用级页面边界，不属于项目 Spec。

## 插槽也由数据声明

Card 支持 header、footer 命名插槽。要展示容量工具，就在该 Card 的 slots.footer 中显式写 CapacityPlanner 节点；不写便没有工具，也不由某个抽象内容类型自动生成它。

```json
{
  "id": "capacity",
  "type": "Card",
  "props": { "title": "团队容量" },
  "slots": {
    "footer": [
      { "id": "planner", "type": "CapacityPlanner", "props": { "initial": 24 } }
    ]
  }
}
```

## 使用组件样式，不强制文章排版

h1 使用 Heading 组件自身的 Tailwind 样式，Grid 使用 Grid 的响应式布局，Card 使用 Card 的样式。JSON 不需要重复 CSS 值，也不能传入任意样式代码。页面不再使用强制 72ch 宽度或覆盖所有后代标题的 Document 包装。

下方展示的是转换后的 json-render Spec，而非另一套组件实现：

## 校验与编辑

这是白名单组件协议，不是任意 HTML 执行器。未知类型、额外属性、跨 children 与 slots 重复的 ID、错误表格行宽均被拒绝。禁止函数、JSX、组件模块路径和原始 HTML 注入。

工作台“页面节点树 JSON”编辑的是同一棵树。修改节点内容、增删节点、调整 children 顺序或 slots 后，客户端与 POST / PATCH 使用共享 schema 校验，成功后立即用相同渲染器展示。输入错误时保留编辑内容。

这是协议编辑器，不是富文本编辑器；会话更改不写回源码或数据库，也不会改变独立 SSR 路由读取的初始 mock JSON。

组件内部交互控件、标签和状态反馈属于受信任的组件实现，例如 CapacityPlanner 的输入控件；这里的一一对应指源页面节点与 Spec 节点，不声称每个最终 DOM 元素或交互文案都逐项写入 JSON。

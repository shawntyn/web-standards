# 内容先于页面模板

统一的是渲染规则，而不是每份文档的内容结构。三个项目各自维护一个 JSON 文件，正文用有序内容块表达；不再为每个项目强制拼一套指标、卡片与源码区。

- Atlas 是产品说明：段落、范围列表、上手步骤，以及实际需要的容量试算。
- Orbit 是编辑手记：引用开篇，接段落、标题、代码片段与开放问题。
- Field 是分析报告：结论先行，再给数据表、假设与行动列表。

## 源文件与边界

packages/data/src/projects/atlas.json、orbit.json、field.json 是独立内容文件。project-repository.ts 只显式导入和校验；pages/project.ts 只连接应用外壳与正文。

packages/domain/src/content.ts 定义允许的内容块。packages/render/src/projects/project-content-spec.ts 用 content.map 把语义内容转换成 json-render 节点，并按数组顺序设置 children。正文不包含 Tailwind 类名、组件模块路径或 JSX。

ProjectSpecViewRender 与 SSR 页面共用这一转换器和注册表，工作台保存后也使用相同的正文呈现。添加段落、删除块或调整顺序只修改内容 JSON，不修改动态路由。

## 内容块

每个块都有稳定且文档内唯一的 id 和一个 type。

- paragraph：text。
- heading：text、level（2 或 3）。页面主标题来自项目名称，不允许正文再插入 h1。
- list：items，可选 ordered。
- quote：text，可选 attribution。
- code：language、code，仅显示文本，不执行。
- table：caption、columns、rows，每一行必须与列数对应。
- callout：title、text。
- capacity-plan：title、description、initial。映射为 ContentSection 的 interactive 命名插槽，只有 Atlas 使用这个特殊组件。

未知类型、重复 ID、错误表格行宽和额外属性都会在业务校验时拒绝。内容 ID 和内部 slot ID 使用不同命名空间，避免覆盖节点。

## 简洁的阅读排版

## 编辑与验证

工作台的“正文内容 JSON”字段可修改同一份内容块。保存前先解析 JSON，再进行共享 schema 校验；服务端 POST / PATCH 同样校验。错误保留输入，成功后会话详情立即使用新内容。这里刻意展示协议编辑器，不把它冒充富文本编辑器。

独立 SSR 路由仍读取仓库内的原始 mock JSON。会话修改不写回源码，不跨标签页同步，也不会改变部署后的服务端数据。

# 数据图表 · 查询结果不是 UI Spec

LineChart、BarChart、DistributionChart、ProgressList 都是自研组件，位于 packages/ui；不取数、不排序，不依赖业务仓储。它们经同一个 catalog / registry 和官方 Renderer 渲染。数据实验室路由为主站 /analytics/commerce、/analytics/empty、/analytics/zero。

## 一条可检查的数据链

1. packages/data/src/analytics/fixtures：模拟数据库驱动返回的 daily、channels、statuses、goals 聚合 rows。
2. repository.ts：查询场景白名单及 Zod 校验，不执行 SQL，也不连接真实数据库。
3. display.json：独立声明标题、布局、组件顺序、单位、空态文案和数据绑定。
4. mapping.ts：显式 rows.map，将 day/order_count 转为 label/value；目标值映射为 value/max；表格单元格映射为字符串。
5. projectContentSpec：复用原有声明式内容转换，生成官方 Spec；catalog 校验后交给注册表。

页面同时展示查询 rows、展示配置与生成 Spec。调试快照排除调试节点本身，防止递归膨胀。此流程不修改项目内容编辑协议，也不把业务字段隐式补成标题。

## 空结果与无障碍

- 折线图使用语义 SVG 和可读数据表，不依赖颜色表达数值。
- 分类图和分布图保留每一项的标签、真实值与单位。
- ProgressList 使用有名称的原生 progress；value 必须在 0 到正数 max 之间。
- 空数组明确为空结果，全零数据仍保留全部行，占比为 0%，不生成 NaN。
- 当前是非负计数的展示契约；不接受负数、非有限值、null。金融盈亏等有符号场景应另定义契约，不能默默夹到零。
- 查询结果顺序就是展示顺序。模拟的 daily 已按日期排列；真实 repository 应通过 ORDER BY 保证，而不是图表自行重排。

## 已确定的项目选择

记录实际技术栈、包管理器、Node 要求、版本来源与安装命令。新建/升级核实官方兼容性；日常修改遵循 lockfile，不擅自更新版本。

记录主站与文档是否独立部署：独立应用用 apps 目录；单应用内部布局才用 route groups。写明实际目录与包 exports，不把示例路径当成强制标准。

## 实现约束

- 自写基础 UI，Tailwind utilities 实现组件样式；共享 CSS 只维护 tokens/base。每个组件独立文件，入口仅导出，按职责拆开数据、校验、转换、状态和视图。
- 共享渲染器，不强制共享页面模板；独立 JSON 示例有真实结构差异。
- 数据明确声明语义、内容、顺序、布局和 slots；mapper 仅校验/转换，不新增源未声明的节点。明确采用的源协议、目标 Spec 与一对一别名。
- 经过官方 json-render、catalog 与受信任 registry；特殊组件通过已声明命名 slot 接入。JSON 不执行代码。
- 保持 SSR 动态路由、真实 404、合理 Server/Client 边界；文档用 MDX，示例走共享 Renderer。
- 表格与表单有真实 mock 新建/编辑闭环、校验和错误恢复；保留正文与 slots，明确存储生命周期和迁移策略。
- 组件自身默认样式与交互行为不等于 mapper 注入；不强制 Markdown 外观。

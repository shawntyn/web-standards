# 行为验收与证据

完成实现或规范审查前按受影响范围使用。检查程序行为，不只匹配目录名、文档措辞或截图外观。

## 数据与映射

- 遍历源树与 Spec：每个源 ID 恰好对应一个元素；未知类型/props/slots、重复 ID、缺失引用明确拒绝。
- 新增、删除、重排源节点后，输出出现相同变化；删除 h1 不自动补标题，删除 slot 不补工具。
- 声明 h1/h2 等，实际 SSR 输出的语义标签正确；不得仅用 div + 字号模拟。
- props 语义与 children/slots 顺序保留；仅改变正文外元数据不能凭空改变详情 Spec。
- 源样例独立且实际组件结构不同；新增样例不需要复制 renderer 或修改固定页面模板。
- registry 与 catalog 一致，特殊组件在预注册范围内；JSON 无执行代码路径。

## 编辑闭环

- 从真实表格选择记录，进入编辑表单；新建及编辑实际经过提交接口，不只是替换文本。
- 测试合法提交、字段/JSON错误、pending防重复提交、失败保留草稿、重试、取消、空结果与成功回显。
- 编辑保存保留完整正文、children、slots；未提交修改不污染已保存记录。
- 客户端和服务端都校验，不依赖浏览器校验作为唯一防线；验证 mock 生命周期及旧存储兼容策略。
- 按业务需要决定删除、分页等范围，不能因清单存在便扩展未经请求的功能。

## 架构与界面

- 独立应用/route groups 选择符合部署边界；跨包走 exports，依赖无循环；入口没有堆业务实现。
- 基础组件独立文件，样式为可扫描 utilities；tokens/base 与组件样式边界清楚。
- Next 生产构建通过；真实路由 HTML 包含内容，未知 slug 返回 404，必要错误边界有效。
- MDX 正文与共享 json-render 示例实际可加载，不测已废弃的影子实现。
- 浏览器可用时检查 hydration、控制台错误、键盘、焦点、表单标签、窄屏/溢出和交互；无法执行则明确未覆盖，不用 DOM 模拟声称浏览器通过。

## 执行与报告

从目标 package.json 读取真实脚本，按顺序运行格式、lint、类型、契约/交互测试、构建和生产 HTTP 检查。禁止为通过验证而关闭检查。仅文档/Skill 变更可限定为语法、引用、示例有效性和行为演练，说明范围。

交付记录应区分：

1. 静态检查和单元/DOM 测试。
2. 生产构建与真实 HTTP / SSR。
3. 部署状态与实际发布版本。
4. 登录后线上浏览器视觉/交互。

每项标明实际通过、失败或未执行。公开 GitHub、私有预览和用户验收不是同一状态。保留已有发布目标和部署专用配置；不要把上次成功或“无错误日志”当作本次全面验收。
